# 复盘协议

本文件是第 0 步「待复盘判定」与复盘执行规则的权威定义。一场比赛何时进入复盘队列、复盘的校准口径、以及谁被允许改写谁的记忆，都以本文件为准。

复盘 agent 是 `football-match-reviewer`，其 manifest 持有执行的细节（如何提取冻结预测、如何归因）；本文件定义的是**判定与边界**。

本文件与两个姊妹文档分工不同，各管一段，不互相重复定义：

- `handoff-contracts.md` 持有 analyzer → reviewer 的**字段契约**，以及「reviewer 直接 Read `-analysis.md`，不走主会话转述」的规则。
- `artifact-templates.md` 持有 `<slug>-review.md` 的**文件骨架**，含「本轮记忆修订」表与「样本量声明」节。

本文件只定义规则本身，不复制上述两处的表结构与字段清单。

---

## 一、待复盘判定（无状态文件）

一场比赛满足**全部三条**即为待复盘：

1. 存在 `<slug>-analysis.md`
2. 目录名的日期**早于今天**（目录名即比赛日）
3. 不存在 `<slug>-review.md`

**文件名就是状态。** 不引入索引文件、数据库或任何「已复盘清单」之类的额外状态——判定逻辑每次现扫 `matches/` 目录即可，无需维护旁路记录。

删掉 `<slug>-review.md` 即让该场重回队列。这是刻意设计，便于重跑：想重算一次校准，删文件即可，无需改任何配置。

三条缺一即非待复盘：没有 analysis 无从复盘；日期未到（或等于今天）说明比赛可能还没打完；已有 review 说明已复盘过。

## 二、静默规则

无待复盘项时**完全静默**。不要输出「已检查，无待复盘项」之类的话——每一步都汇报会让流程变吵，而这一步在多数情况下本来就无事发生。

静默不等于跳过检查：检查必须做，只是结果为零时不发声，直接进入第 1 步。

## 三、比赛未结束的处理

WebSearch 拿不到终场比分 → **不写 `<slug>-review.md`、不报错、不重试**。

这保证「没有结果」和「已复盘」不会被混为一谈：一旦给未结束的比赛写了 review，该场就因「存在 review」而永久退出复盘队列，一次失败抓取就会造成永久漏盘。所以宁可本轮不写，留待下次判定时再次进入队列。

reviewer 从磁盘直接 Read `<slug>-analysis.md`（不接收主会话转述的摘要），其提取字段的契约见 `handoff-contracts.md` 的「analyzer → reviewer」一节。

## 四、校准口径

### 1X2（算分）

- **Brier score**（多分类，单场）：`BS = Σ_k (p_k − o_k)²`，k ∈ {主胜, 平, 客胜}，`p_k` 为预测概率，`o_k` 对实际结果取 1、其余取 0。取值 0–2，越小越好。
- **log loss**：`−ln(p_实际结果)`，取实际发生那一项的概率，越小越好。
- **均匀基线**：每项 1/3 时 `BS ≈ 0.667`、`log loss ≈ 1.0986`。**必须与基线并列展示**——脱离基线的绝对值没有意义。报告里模型数字与基线数字必须同时出现，缺了基线，0.55 这样的数字没有任何含义。

### 其他市场（只记命中，不算分）

让球与总进球**只记命中 / 走盘，不算分**。口径简单且不易出错。

### 投注方案（若有 plan.md）

按**当时实际可得赔率**算盈亏，不按模型的最低可接受赔率。

## 五、记忆写权限（关键，不可含糊）

### 谁拥有什么

- `football-match-reviewer` 拥有自己的记忆目录：`.claude/agent-memory/football-match-reviewer/`。
- 其余 agent（analyzer、gatherer、strategist）各自持有自己的记忆目录；它们的记忆条目里既有**论断**（假设），也有**证据 / 置信**标注。

### 核心不对称

**假设由 analyzer 持有，证据只能由比赛结果产生。** analyzer 写下「小球常被高估」这类假设时，手上只有赛前情报；真正能证实或推翻它的证据，要等比赛结束才出现，而赛后看结果的只有 reviewer。

因此 reviewer 被**显式授权**修订其他 agent 记忆条目中的「证据 / 置信」部分——这是整套复盘能闭环的前提。

### 可以

- 追加或更新证据标注：n 计数、胜负记录、置信升降级。例如在既有条目上追加「n=2 均失败，降级为待验证」。

### 不可以（硬边界）

- **改写原始论断本身（无论是否留痕）。** 证据足以推翻论断时，正确做法是**新写一条记忆并以 `[[旧条目名]]` 链接**旧条目，保留推理痕迹。改写原文会摧毁这套循环赖以成立的审计链。
- 不触碰证据 / 置信以外的任何部分。

### 留痕

每次修订都必须在 `<slug>-review.md` 的「本轮记忆修订」表里留痕——改了哪条、改了什么、为什么改。该表的列定义见 `artifact-templates.md`，本文件不复制。

### 为什么这条授权存在

不给这条授权，错误假设永远不会被降级，校准闭环就是断的。这正是用户此前手工在做的事：`extreme-mismatch-ucl` 条目上那条「n=2 均失败，降级为待验证」的标注，就是本协议要形式化、并交到 reviewer 手里的动作。

### 并发约束（硬性）

修订**其他** agent 的记忆条目时，必须在写入前**重新 Read 该条目的最新内容再追加**，不得基于 dispatch 时的旧快照写入——两个 reviewer 从同一快照并行追加同一条目，后者会覆盖前者。

因此：**多个待复盘场次若可能修订同一条目（同一 agent 的同一主题），必须串行 dispatch，不得并行。** 互不相干、或只读不写的复盘可以并行。

## 六、样本量纪律

n < 5 时，结论一律标注「样本不足，仅作观察」。

**不得据以调参——这是禁令，不是建议。** 在 n < 5 的样本上调整任何参数、λ 或概率偏移，一律禁止，没有例外。把小样本噪声抬成规则，正是模型退化的方式。

`<slug>-review.md` 的样本量声明怎么写、以及 n < 5 时该节必须写「样本不足，仅作观察」，见 `artifact-templates.md`；本文件不复制该节。
