# 产物模板

本文档定义各阶段产物在磁盘上的骨架。产物文件名固定，见下表；格式以「格式权威」列所指为准。若同一产物在本文件与对应 agent manifest 之间出现冲突，以「格式权威」列所指为准。

| 产物 | 路径 | 格式权威 |
|---|---|---|
| 情报 | `matches/YYYY-MM-DD/<slug>-intel.md` | `football-intelligence-gatherer` manifest |
| 分析 | `matches/YYYY-MM-DD/<slug>-analysis.md` | `football-match-analyzer` manifest |
| 复盘 | `matches/YYYY-MM-DD/<slug>-review.md` | **本文件** |
| 汇总 | `matches/YYYY-MM-DD/summary.md` | **本文件** |
| 方案 | `matches/<本轮最早比赛日>/plan-NN.md` | `lottery-strategist` manifest |
| 方案复盘 | `matches/<该方案所在比赛日>/plan-NN-review.md` | **本文件** |

> 跨比赛日批次：`summary.md` **每个比赛日一份**，落在各自的比赛日目录；方案文档落在本轮**最早**的那个比赛日目录，命名为 `plan-NN.md`。
>
> **方案永不覆盖。** 写入前先 `ls` 目标目录下已有的 `plan-NN.md`，取下一个可用序号（无则 `plan-01.md`）。注意 `plan-*.md` 会连 `plan-NN-review.md` 一起匹配到——**看序号时只认方案本体**，review 文件不占号。同一天出第二轮方案时，第一轮必须原样保留——方案是真实支出的记录，也是 reviewer 事后要逐份评分的对象，覆盖即销毁审计链。
>
> 方案复盘的命名随方案走：`plan-03.md` 的复盘就是 `plan-03-review.md`。方案被删，它的复盘一并失去意义。

## 命名规范

- **slug 格式：** `slug = <主队>-vs-<客队>`，全小写、连字符分隔（如 `arsenal-vs-liverpool`）。
- **日期目录格式：** `matches/YYYY-MM-DD/`，日期目录用**比赛日**，不是分析日。

`handoff-contracts.md` 中的 `<slug>`、`<date>` 占位符按此解释；两文件须保持同步。

## 格式权威声明

`-intel.md` 与 `-analysis.md` 的格式**以对应 agent manifest 为准**，本文件不复制、不覆盖，避免两处定义漂移。以下概述仅作快速索引，与 manifest 冲突时以 manifest 为准。

### `-intel.md`（情报）

格式沿用 `football-intelligence-gatherer` manifest 的 Output Format：四个情报分类 + 数据时点。

- 四个情报分类：赔率 / 阵容 / 近期状态 / H2H。
- 采集时点：见 manifest 的 Output Format 第 4 项（Data timestamp）。
- 可信度标记：见 manifest 的 Operational Standards；本文件不复制该标记集合。

### `-analysis.md`（分析）

格式沿用 `football-match-analyzer` manifest 的 Output Format Requirements：1X2 / 正确比分 / 亚盘 / 总进球 / 关键洞察 / 推荐。

### `summary.md`（汇总）

多场汇总表，每行一场；单场也写，保持产物一致。列：

| 场次 | 情报完整度 | 主胜 | 平 | 客胜 | 正确比分前 10 | 让球（主线及相邻线） | 总进球（含 1.5、2.5、3.5） | 边际价值 |
|---|---|---|---|---|---|---|---|---|

### `-review.md`（复盘）

本文件定义，完整骨架如下：

```markdown
## 复盘：<主队> vs <客队> | <赛事> | <比赛日>

**结果来源：** WebSearch / 用户提供 —— <来源说明>
**情报完整度（当时）：** 高 / 中 / 低

### 实际结果

| 项 | 值 |
|---|---|
| 最终比分 | X-X |
| 半场比分 | X-X |
| 关键事件 | <红牌 / 伤退 / 点球> |

### 校准指标（1X2）

| 指标 | 模型 | 均匀基线 | 判定 |
|---|---|---|---|
| Brier score | 0.XXX | 0.667 | 优于 / 劣于 |
| Log loss | X.XXX | 1.099 | 优于 / 劣于 |
| 最高概率项命中 | 是 / 否 | — | — |

> Brier score 与 log loss 必须与均匀基线并列展示。脱离基线的绝对值没有意义。

### 其他市场

| 市场 | 预测 | 实际 | 命中 |
|---|---|---|---|
| 正确比分 | 前 10 含 X-X，实际比分概率 X.X% | X-X | 是 / 否 |
| 让球 | <线> 取 <方向> | 赢 / 输 / 走盘 | 是 / 否 |
| 总进球 | <线> 取 大 / 小 | 总进球 X | 是 / 否 |

### 投注方案

本场若被方案覆盖，这里由**方案复盘**补写指向行，**单场复盘不填**。方案是整份结算的，盈亏表在 `plan-NN-review.md`；写在这里会把同一笔本金按场次重复计一次。

> 本场被 `matches/<比赛日>/plan-NN.md` 覆盖；其结算见 `plan-NN-review.md`。

**一份方案一行。** 同一天出过两轮方案的，本场会有两行，各自指向自己的复盘——不要合并成一行，也不要只留最后一份。

未被任何方案覆盖时，本节留空——「本节为空」本身就是没有方案覆盖的信号。

### 归因

**这是复盘的核心产出。** 不是复述对错，而是指明哪条情报或哪个建模假设失效：

- [失效点 1] —— 具体到是哪条情报判断错了，或哪个 λ 估计偏了
- [失效点 2]

若预测命中，说明是**因为预想的机制**命中，还是**碰巧**命中。答案对但机制错的，仍然是缺陷。

```

> `本轮记忆修订` 表已记录「改了哪条记忆、为什么改」。当新证据推翻一条既有结论时，正确做法是**写一条新记忆并链接旧条目**（`[[旧条目名]]`），而非改写原文（设计规范 §5.3.3）。

### `plan-NN-review.md`（方案复盘）

本文件定义，完整骨架如下。**一份方案一个文件，写在方案旁边**——方案是整份结算的，不摊到各场 `-review.md` 里。

```markdown
## 方案复盘：plan-NN | <本轮比赛日范围>

**方案文件：** `matches/<比赛日>/plan-NN.md`
**结算依据：** 各场 `-review.md`（逐场列出路径）

### 比赛结算

| 比赛 | 比赛日 | 实际比分 | 结果 |
|---|---|---|---|
| <主队> vs <客队> | YYYY-MM-DD | X-X | 胜 / 平 / 负 |

> 覆盖的每一场都必须先有 `-review.md` 才允许结算。**缺一场即不写本文件** —— 原因与判定见 `review-protocol.md` §一「方案队列」。

### 注单结算

| 注 | 玩法 | 选项 | 赔率 | 金额 | 命中 | 盈亏 |
|---|---|---|---|---|---|---|
| … | … | … | … | … | … | … |

**合计：** 投入 X 元，回收 X 元，回收率 X%

> 赔率取方案里**当时写下**的赔率，不取事后赔率。玩法按**竞彩**规则结算；让球胜平负用**竞彩让球数**，不是 analyzer 报的亚盘盘口。混合过关须全中。

### 归因

**这是方案复盘的核心。** 不重述命中与否，而是指明方案层面哪一步错了：选场、选玩法、串关结构、注额分配，还是「本来就不该下」。
```
