**审计前必须核对产物落盘时间。** 本仓库存在 `-intel.md` 的落盘时间**晚于比赛日**的情况：`matches/2026-09-06/arsenal-vs-chelsea-intel.md` 的采集时间戳为 2026-09-11，且文件自述为「赛后还原赛前视角」的重构稿——它已含有终场比分，只是把叙述包装成赛前口径。

**Why:** 该文件在「比赛识别」一节直接写出了实际比分与进球者，同时还标注了两队预测首发为 `PREDICTED`。作为**上下文**它有参考价值；但作为**证据**它不可用——用一份事后重构稿去核对模型赛前是否「应该知道」某事，会系统性高估情报的赛前可得性，把不可能赛前获得的信息算成模型的失误。这会给归因结论注入错误。

**How to apply:** 复盘时被评分的冻结点是 `-analysis.md` 与 `plan.md`（它们的落盘时间应早于开球）。intel 只用于理解模型的输入语境，并在报告中显式标注其「重构稿」性质。核对方法：读文件末尾的 Data Timestamp 节，与目录名（比赛日）比较；若晚于比赛日，即为重构或追补稿。此观察不针对某一 agent 的判断质量，只关乎证据可用性——不要在报告里把它写成一个失效点。
